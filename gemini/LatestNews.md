# 每週新聞與輿情掃描器（LatestNews）— Gemini / Claude 共用版

> **一句話任務**：以本 repo 追蹤的公司與主題為準，蒐集「過去 7 天」與持股有關的新聞和社群輿情，查核真偽後寫入 `gemini/LatestNewsResult.md`，並列出「下一輪要深入分析的項目」。
>
> **唯一輸出檔**：`gemini/LatestNewsResult.md`（只保留 7 天內的新聞與輿情，超過 7 天的直接刪除）。
>
> **🔁 每輪必做：整份重寫（Final Rewrite）**：每次執行本檔，**不論有沒有新新聞、不論搜尋成功或失敗**，結束前都必須把 `gemini/LatestNewsResult.md` **從頭到尾重新寫一份，整檔覆寫**（Step 6）。**禁止**在舊檔上局部修補、刪幾行、或把新內容接在後面。沒有重寫＝本輪沒做完。
>
> **讀者**：初級股票分析師＋下一輪執行的 AI。寫法規範見第 3 章「寫作規範」。
>
> **兩個品質目標（和「7 天窗口」「防幻覺」同等重要）**：
> - **看得懂**：剛入行、沒追過這週新聞、沒讀過這家公司年報的分析師，**只靠這份檔案**就能看懂「發生什麼 → 為什麼重要 → 對哪檔持股的 EPS／配息／估值有什麼影響 → 接下來要盯什麼」。
> - **夠詳細**：每則新聞都要把背景、關鍵數字（含比較基準）、影響路徑、每股影響、反方觀點、後續觀察點寫出來（W3 欄位）。**寧可長，不可只丟一句標題**；但每一句都要有資訊量，不灌水。
>
> **執行模式**：`/goal` 全自動。不中途向使用者提問；遇到錯誤記錄後繼續，一路做完 Step 0 → Step 8。
>
> **適用模型**：Gemini（Pro / Flash）與 Claude（Opus / Sonnet / Haiku）都要能照做。本檔只用「步驟＋條列＋少量表格」，不用任何模型專屬語法。

## 0. 名詞與路徑（先讀，後面會一直用）

- `REPO_ROOT`：FinancialReport repo 根目錄。Windows 本機通常是 `d:\FinancialReport`；Linux / 雲端通常是 clone 下來的資料夾（例如 `/home/user/FinancialReport`）。**以當前工作目錄為準，不要寫死。**
- `TODAY`：執行當下的台北日期（UTC+8），格式 `YYYY-MM-DD`。**必須實際執行指令取得**，嚴禁憑印象。
- `CUTOFF`：`TODAY − 7 天`。新聞日期 **≥ CUTOFF** 才能留在輸出檔；**< CUTOFF 一律刪除**。
  - 例：`TODAY = 2026-09-30` → `CUTOFF = 2026-09-23` → 只保留 09-23 ～ 09-30。
- `新聞日期`：以「事件首次公開日」為準（公司公告日、官方發布日、媒體首發日取最早者）。**轉載日、整理文發布日都不算**。
  - 例：福耀 8/23 官網上架太陽能天窗、9/22 媒體再寫一次 → 新聞日期是 8/23，不是 9/22。
- `持股清單`：`REPO_ROOT` 根目錄下所有「公司資料夾」（見 Step 1）。
- `本地分析檔`：`<公司資料夾>/hourAnalysisResult.md`（第一行是更新時間戳，第 1 章有「一句話結論」與「本輪最重要的 3 件新事」）。
- `舊檔`：本輪開始時的 `gemini/LatestNewsResult.md`。**只讀、不改**；它只是 Step 2 的輸入素材。
- `PREV_TS`：舊檔第一行的時間戳（舊檔不存在就記為 `首輪`）。
- `事件卡`：「一則一事」的暫存筆記（記在思考或 scratchpad，不寫進 repo），欄位：`日期｜標題｜內容與數字｜每股化｜多空｜重要性｜對應持股｜來源 URL｜狀態（保留／刪除／修正／新增）`。Step 6 只用事件卡來寫新檔。

## 3. 寫作規範（讀者：初級股票分析師）

> 適用範圍：只約束輸出檔 `gemini/LatestNewsResult.md`。本 prompt 自己、各公司的輿情 md 不受限。

### W1 讀者畫像

- **看得懂**：財報三大表、EPS、PE、ROE、毛利率、殖利率、市值這類基本指標 → **不用解釋**。
- **不熟悉**：各國央行與債市用語、各地市場制度、產業術語、公司自定義指標 → **首次出現補一句白話**。
  - 例：「升息 1 碼（0.25 個百分點）」「DPU（REIT 每單位配息，相當於股票的每股股利）」「TOB（公開收購，日本的收購要約）」「地天板（開盤跌停、收盤漲停）」「HIBOR（香港銀行間拆借利率，港元貸款的基準利率）」「LTV（負債 ÷ 資產，REIT 的槓桿指標）」。
- **沒追過**這週新聞、**沒讀過**這家公司年報 → 每則新聞都要自帶背景，不假設讀者知道前情。

### W2 必守寫法（12 條）

1. **先結論、後細節**：每個大區、每個市場、每家公司開頭先寫 1 句導讀：「本區重點：…」。
2. **標題就是白話結論**：看標題就知道發生什麼、是好是壞。
   - ❌ `日銀新階段`
   - ✅ `日銀暗示升息會加快 → 借浮動利率的 2971 利息負擔變重`
3. **術語處理**：依 AGENTS.md，專有名詞首次出現寫 `中文（英文）`，如「日本央行（BOJ）」；W1 的冷門術語再補**一句**白話。同一術語之後不再重複解釋。**不在檔尾附名詞表**。
4. **數字一定要有比較基準**：數字後面寫「跟上次／去年同期／市場預期／本地分析比」與「所以代表什麼」。
   - ❌ `PMI 50.1`
   - ✅ `製造業 PMI 50.1（8 月 49.8；50 以上代表景氣擴張）→ 睽違 3 個月重回擴張，對中資港股是正面訊號`
5. **寫出影響路徑（最重要）**：新聞 → 影響哪個經營變數（利率／售價／成本／銷量／匯率／資金流）→ 財報哪一行（營收／毛利／利息支出／投資收益／減損）→ EPS、配息或估值。**寫不出路徑的新聞，就是跟持股無關，降為 LOW 或刪掉。**
6. **能量化就量化、每股化**：寫成 `約每股 −0.05 HKD，約當 2026E EPS 的 −1.2%`。用推估就寫明 `（推估：假設…）`，不可和實績數字混在一起。
7. **單位、幣別、日期寫滿**：`102.59 美元／桶（2026-09-29 收盤）`；港股以 HKD 為主要幣別，人民幣放括號並寫匯率。
8. **代碼標市場**：`02318（港交所）`、`2971（東證）`、`2881（台灣證交所）`、`UHS（NYSE）`、`688432.SH（上海科創板）`。
9. **句子要短**：一句只講一件事，盡量 ≤ 40 個中文字；不要連續堆 3 個以上縮寫。
10. **多空兩面都寫**：HIGH 新聞一定要有「反方觀點／不確定性」，說明為什麼可能不照這個方向走。
11. **每區結尾寫「所以呢」**：每家公司、每個宏觀小節最後 1 句寫「投資人該做什麼／盯什麼」。
12. **不重複、不灌水**：同一事件只在最相關的一區寫完整版，其他區用一行「見 4.2」連過去。詳細 ≠ 冗長：每一行都要有新資訊。

### W3 單則新聞的欄位（詳細度標準）

> 欄位名稱加粗、一行一欄、順序固定。**HIGH 寫滿 10 欄；MEDIUM 至少寫 ①②④⑤⑧⑩；LOW 至少寫 ①⑤⑩。**

```markdown
- 🔴/🟢/⚪ **[MM-DD] 白話標題（看標題就知道發生什麼、是好是壞）**｜重要性：HIGH/MEDIUM/LOW｜可信度：⭐/◐/⚠️
  - **① 發生什麼**：2–3 句白話。誰、做了什麼、何時生效、規模多大。
  - **② 關鍵數字**：每個數字＋單位＋日期＋比較基準＋一句「代表什麼」。多個數字就用子條目逐一列。
  - **③ 背景**：1–2 句前情。為什麼會發生、之前的狀態是什麼（可引用 CUTOFF 以前的舊事實當背景，但要標日期）。
  - **④ 影響路徑**：新聞 → 經營變數 → 財報科目 → EPS／配息／估值（用「→」串起來）。
  - **⑤ 對持股**：逐檔一行：`代號 名稱（交易所）`：🟢/🔴/⚪＋理由＋每股影響（實績，或「推估＋假設」；無法量化就寫原因）。
  - **⑥ 市場反應**：當天或隔天的股價、殖利率、匯率變化（有才寫；沒有就寫「尚無明顯反應」）。
  - **⑦ 反方觀點／不確定性**：為什麼可能不照這個方向走；還缺什麼資訊。
  - **⑧ 接下來看什麼**：具體日期或指標＋門檻＋觸發後的意義（例：`下次日銀會議（MM-DD）：若升到 1.5% → 2971 每口 DPU 推估再少約 X 円`）。
  - **⑨ 與本地分析**：一致／🔄 不同（本地寫 X〔檔案路徑、日期〕，新聞寫 Y）／本地未提及。
  - **⑩ 來源**：[名稱](URL)；HIGH 至少 1 個官方或 2 個獨立媒體。
```

### W4 壞寫法 → 好寫法（對照）

- ❌ 太簡略（2026-09-30 版實際寫法）：
  ```
  - 🔴 **[09-24～09-28] 10 年期 JGB 殖利率 3.07%～3.08%，1996 年來新高** HIGH
    - 對持股：`2971`（浮動利率借款多）🔴；J-REIT 整體利差收窄 🔴
  ```
  問題：沒說 3.08% 跟以前比多高、「利差」是什麼、2971 的 EPS／DPU 會少多少、接下來看哪一天。

- ✅ 合格寫法（示範結構，數字須以當輪查到的來源為準）：
  ```
  - 🔴 **[09-28] 日本 10 年期公債殖利率升到 3.08%、30 年新高 → 借浮動利率的 2971 配息壓力變大**｜重要性：HIGH｜可信度：⭐
    - **① 發生什麼**：日本 10 年期公債（JGB）殖利率 9/28 收 3.08%。這是 1996 年以來最高。
    - **② 關鍵數字**：
      - 3.08%（9/1 首度站上 3.0%；一個月再升約 0.08 個百分點）→ 長期借錢成本持續墊高
      - 2971 固定利率借款比 22.9%（本地分析檔）→ 近 8 成借款會跟著利率調升
    - **③ 背景**：日本央行（BOJ）9/18 已升息到 1.25%。路透 9/30 報導 BOJ 之後升息會「更快、更規律」。
    - **④ 影響路徑**：JGB 殖利率↑ → 銀行放款利率↑ → 2971 利息支出↑ → 可分配收益↓ → DPU↓；同時 REIT 殖利率與公債的利差（多出來的報酬）縮小 → 估值承壓。
    - **⑤ 對持股**：
      - 2971 ES-CON 日本 REIT（東證）：🔴 推估利率每升 0.25 個百分點，每口 DPU 約少 X 円（約當 DPU 的 −Y%；假設浮動借款 Z 億円、全數重新定價）
    - **⑥ 市場反應**：2971 09-30 盤中 104,900 円，約 2 年新低。
    - **⑦ 反方觀點**：日圓轉強、通膨回落的話，BOJ 可能放慢升息；2971 也可能提高固定利率比。
    - **⑧ 接下來看什麼**：下一次 BOJ 利率會議（日期以 BOJ 官網為準）；2971 下一次財報的借款明細（固定比有無提高）。
    - **⑨ 與本地分析**：一致（`2971ES-CON日本REIT/hourAnalysisResult.md`，2026-09-30 版）。
    - **⑩ 來源**：[來源 A](URL)、[來源 B](URL)
  ```
  （X、Y、Z 在實際執行時必須用本地分析檔或財報的真實數字算出，**不可照抄範例**；算不出就寫「無法量化：原因」。）

## 4. 執行流程總覽

```
Step 0  取 TODAY / CUTOFF ＋ git pull
Step 1  從 repo 建立「關注地圖」（我到底想看哪些新聞）
Step 2  讀舊檔（只讀不改）→ 拆成事件卡 → 標出過期／待查／保留
Step 3  搜尋：宏觀 → 個股 → 社群輿情（新增事件卡）
Step 4  查核：交叉驗證、對帳本地分析、標可信度（更新事件卡）
Step 5  產生「下一輪分析項目」
Step 6  🔁 Final Rewrite：用事件卡整份重寫 LatestNewsResult.md（一次覆寫，時間戳最後蓋）
Step 7  驗收（Definition of Done）→ 不過就回 Step 6 再整份重寫
Step 8  git commit / push ＋ 精簡摘要
```

> **時間不夠時的保底路徑**：Step 0 → Step 2 → Step 6 → Step 7 → Step 8。也就是說，就算一條新新聞都沒找到，也要把舊檔過期的刪掉、整份重寫、蓋新時間戳後交付。

---

## Step 0 — 取日期與同步

1. 實際執行指令取台北時間，得到 `TODAY` 與完整時間戳 `yyyy/MM/dd HH:mm:ss`。
2. 算出 `CUTOFF = TODAY − 7 天`。
3. `git pull`（Gemini 本機：`git pull origin master`；Claude 雲端：拉當前工作分支與 `origin master`）。衝突 → `git stash` → `pull` → `stash pop`；網路失敗重試 3 次（2s / 4s / 8s），仍失敗就記錄後**繼續**。
4. **pull 之後**讀舊檔第一行，記為 `PREV_TS`（Step 6 表頭與 Step 7 驗收要用）。

## Step 4 — 查核（最容易出錯的地方）

### 4.1 每條新聞都要過的 5 個檢查

1. **日期對嗎？** 事件首次公開日 ≥ CUTOFF？
2. **來源真的有這句話嗎？** 打開 URL 讀原文，不要只看搜尋摘要。
3. **HIGH 有交叉確認嗎？** 官方 1 個或獨立媒體 2 個。
4. **數字和本地分析檔一致嗎？** 不一致 → 兩個都寫，標 `🔄 與本地分析不同`，並產生下一輪項目。
5. **是新消息還是舊聞重炒？** 媒體「再報導」不算新聞。

### 4.2 本 repo 已發生過的錯誤（不要再犯）

- 把央行會議日期寫錯（日銀 2026-09-18 升息被寫成 09-24；聯準會 09-16 升息被寫成 09-25）。
- 把「放寬」寫成「不鬆綁」（台灣央行 2026-09-17 其實把第二戶房貸成數由 6 成放寬到 7 成）。
- 把舊產品消息當新聞（福耀太陽能天窗 8/23 已上官網）。
- 把大型券商持股的日常增減（如摩根大通 H 股持股在 15.85%～16.13% 間來回）寫成重大利多；這類多屬託管／借貸池變動，重要性最多 LOW。
- 只看盤前標題就下結論（9/30 內地房地產股開盤跌停、盤中又 V 型翻紅，要寫完整走勢）。
- 承銷價、配息等數字與本地分析檔不同卻沒標出（湧盛暫定承銷價媒體寫 75 元，本地分析寫 85 元）。
- **寫得太簡略、初級分析師看不懂**（2026-09-30 版）：「對持股：`02318` 🟢 情緒改善」「J-REIT 整體利差收窄 🔴」只給方向不給理由；「1 碼」「地天板」「利差」沒解釋；PMI、殖利率只丟數字沒比較基準。→ 依寫作規範 W2、W3 寫滿欄位。

### 4.3 重要性分級

- **HIGH**：可能讓 EPS、配息或估值變動 ≥ 5%；或公司治理／法遵重大事件；或央行利率、重大政策
- **MEDIUM**：影響 1%–5%，或對趨勢有指標意義
- **LOW**：影響 < 1% 或純市場情緒

### 4.4 輿情可信度標記

- `⭐ 已驗證`：論點中的數字能在財報或官方公告找到
- `◐ 部分驗證`：方向正確但數字無法完全回查
- `⚠️ 未證實`：傳聞、無來源；只放在「傳聞追蹤」區

## Step 6 — 🔁 Final Rewrite：整份重寫 `gemini/LatestNewsResult.md`

> **每輪必做，沒有例外。** 定義：**重寫（rewrite）≠ 修補（patch）≠ 重排（rearrange）**。不是在舊檔上刪幾行、也不是把段落搬位置，而是用事件卡**重新寫出一整份新檔，再一次覆寫舊檔**。

### 6.1 重寫五步驟

1. **收齊事件卡**：Step 2（舊檔保留／修正）＋ Step 3（新增）＋ Step 4（查核結果）＋ Step 5（下一輪項目）。狀態為 `刪除` 的卡不寫進正文，只寫進第七區。
2. **重新排序**：各區內依「重要性 HIGH → MEDIUM → LOW」，同級再依日期新 → 舊。第一區「本週最重要 5 件事」**每輪重選**，不可沿用上一版的 5 件。
3. **重新寫句子**：每張卡依寫作規範 W2 重新組句、依 W3 補滿欄位；數字重新對一次來源，金額**重新每股化**（股數可能已變，不沿用上一版每股數字）。上一版殘留的表格、錯字、模糊日期、只寫方向不寫理由的句子，一律在這一步修掉。
4. **一次覆寫**：在記憶體／草稿中組好**完整全文**，用 Claude `Write`／Gemini `write_to_file`（`Overwrite=true`）**寫一次**。第一行先放佔位字串 `TIMESTAMP_PENDING`。
5. **最後蓋時間戳**：全文寫好後才實際執行指令取台北時間，把第一行的 `TIMESTAMP_PENDING` 換成 `YYYY/MM/DD HH:MM:SS (UTC+8)`（這是本輪唯一允許的局部修改）。時間戳必須晚於 `PREV_TS`。

> 首輪（沒有舊檔）也照這五步走；第七區寫「首輪，無」。

可直接執行的檢查指令（擇一）：

```bash
# Claude / Linux
F=gemini/LatestNewsResult.md
head -1 "$F"; grep -c TIMESTAMP_PENDING "$F"                          # 時間戳；應為 0
for n in 一 二 三 四 五 六 七 八; do printf "%s:" "$n"; grep -c "^## $n、" "$F"; done   # 每區應為 1
grep -nE '^\s*\|.*\|\s*$|\|\s*:?-{3,}' "$F" | wc -l                      # 表格；應為 0
grep -oE '\[[0-9]{2}-[0-9]{2}\]' "$F" | sort -u                          # 列出所有日期，逐一對 CUTOFF
```

```powershell
# Gemini / Windows
$F = "gemini\LatestNewsResult.md"
```

欄位齊全檢查腳本（有 Python 就跑；沒有就人工逐則檢查）：

```python
import re
F = "gemini/LatestNewsResult.md"
need = {"HIGH": "①②③④⑤⑥⑦⑧⑨⑩", "MEDIUM": "①②④⑤⑧⑩", "LOW": "①⑤⑩"}
items, cur, zone = [], None, False
for line in open(F, encoding="utf-8"):
    if line.startswith("## "):                      # 只檢查「四、宏觀」與「五、個股」兩區
        zone = line.startswith(("## 四、", "## 五、"))
    if not zone or line.startswith("#"):
        cur = None
        continue
    if re.match(r"^- [🔴🟢⚪]", line):                # 一則新聞的標題行
        m = re.search(r"重要性：(HIGH|MEDIUM|LOW)", line)
        cur = {"title": line.strip()[:50], "lv": m.group(1) if m else None, "has": set()}
        items.append(cur)
    elif cur and (m := re.match(r"^\s+- \*\*([①-⑩])", line)):
        cur["has"].add(m.group(1))
bad = []
for i in items:
    miss = "「重要性：」標記" if not i["lv"] else "".join(c for c in need[i["lv"]] if c not in i["has"])
    if miss: bad.append((miss, i["title"]))
print(f"四、五區新聞 {len(items)} 則，不合格 {len(bad)} 則")   # 不合格應為 0；新聞 0 則也要人工確認是否真的沒新聞
for miss, t in bad: print("缺", miss, "→", t)
```
