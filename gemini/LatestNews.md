# LatestNews：持股近 30 天新聞與輿情（Gemini / Claude 共用）

## 0. 一句話任務

每輪**先掃 repo 根目錄有哪些股票資料夾**，只蒐集「這些股票」近 30 天的新聞與輿情，查核、每股化、依重要性排名後，**整份重寫** `gemini/LatestNewsResult.md`，跑腳本驗收，最後 commit / push。

- **以股票為主**：每一則都必須對應到至少 1 個根目錄股票資料夾。宏觀新聞（利率、油價、匯率、政策）只有在能寫出「→ 某檔持股每股 EPS／配息／淨值變多少」時才收；寫不出就不收。
- **持股清單每輪重抓**：以根目錄資料夾為準，不寫死、不沿用上一輪清單。資料夾被刪 = 已出清，不搜；新增資料夾 = 本輪就要搜。
- **讀者**：初級分析師（懂財報三大表，沒追新聞）＋下一輪的 AI。
- **全自動**：`/goal` = 不中途提問，一路做到 Step 7；`/boost` = 每條都讀原文、交叉驗證。遇錯記進第八區後繼續，不停下。
- **檔案**：本 prompt（規則，本輪不改）＝`gemini/LatestNews.md`；唯一輸出檔＝`gemini/LatestNewsResult.md`；驗收腳本＝`gemini/LatestNews_check.py`。

## 1. 名詞

- `REPO_ROOT`：repo 根目錄（Windows 本機 `d:\FinancialReport`；雲端 `/home/user/FinancialReport`）。
- `TODAY`：台北時間（UTC+8）今天 `YYYY-MM-DD`，**一定要執行指令取得**。
- `CUTOFF`：`TODAY − 30 天`。新聞日期 ≥ CUTOFF 才留。
- `新聞日期`：該進展的**首次公開日**（公告／官方發布／媒體首發取最早）。轉載、整理文不算新日期。
- `PREV_TS`：舊輸出檔第一行時間戳；`PREV_DATE` 為其日期部分。舊檔不存在 = 首輪。
- `持股`：`--list` 列出的根目錄股票資料夾（Step 1）。
- `本地分析檔`：`<資料夾>/hourAnalysisResult.md`（有「一句話結論」「股數口徑聲明」「本年預估 EPS／DPU」）。
- `本地輿情檔`：`<資料夾>/2026_PublicOpinion.md`、`<資料夾>/<YYYYMM>_輿情新聞.md`。
- `事件卡`：一事一卡的暫存筆記（只在思考或 scratchpad，不進 repo）。欄位：日期｜持股代號｜標題｜內容與數字｜每股影響｜多空｜分數｜可信度｜來源 URL｜🆕｜狀態（保留／刪除／修正／新增）｜理由。
- `🆕`：本輪新增的卡，或卡片日期 ≥ `PREV_DATE`。
- `降溫`：卡片日期距 TODAY > 14 天、急 = 0、幅 ≤ 3 → 分級降一級（HIGH→MEDIUM、MEDIUM→LOW、LOW→刪除），標題加 `｜（降溫）`。幅 = 4 不降溫。
- `N#`：第二區排行榜編號，N1 最重要；全檔引用寫「見 N3」。

## 2. 鐵則（違反 = 重寫）

1. **只寫持股相關**：每則 ⑤ 至少列 1 檔根目錄持股；與持股無關的新聞不收。
2. **30 天窗口**：每則都有單一 `[MM-DD]` 且 ≥ CUTOFF；沒日期或過期一律刪。一事多進展合成一張卡，標題用窗口內**最新進展**日期，不寫日期區間。
3. **防幻覺**：每則都有可點開的 URL 或本地路徑；數字、日期、人名取自原文，**不可用訓練資料補**。查不到就寫「查不到：原因」並記第八區。
4. **查核**：HIGH 要「官方 1 個」或「獨立媒體 2 個」；做不到降級，或標 `⚠️ 未證實` 放第六區（不進排行榜）。
5. **對帳**：與本地分析檔數字不同 → 兩個都寫、標 `🔄`、產生一條下一輪項目。
6. **每股化**：凡跟持股有關的金額，都換成「每股 ±X 幣別，約當 EPS／DPS／DPU 的 ±Y%」；做不到寫 `無法量化：原因` 或 `影響可忽略：原因`。
7. **幣別**：港股（含 H 股、紅籌、港股 REIT、87001 人民幣櫃台）每股一律 **HKD 在前**，原幣放括號並寫匯率；日股 JPY；台股 TWD；美股 USD（ADR 用每 1 ADS）。
8. **一套口徑**：同一檔全檔用同一股數；全檔用同一套匯率（寫在表頭）。
9. **只能整檔覆寫**：輸出檔只用 Claude `Write`／Gemini `write_to_file`（Overwrite=true）／Gemini CLI `write_file` 一次寫入；禁止 Edit、replace、追加。驗收不過 → 重新整份寫。
10. **輸出檔零表格**、繁體中文（台灣用語）；代號、路徑、URL 保留原文。
11. **零阻塞**：網站被擋、逾時 → 換工具或來源；全失敗記第八區，繼續。沒寫檔就結束 = 失敗。

## 4. 流程

```
Step 0  時間、git pull、匯率
Step 1  列出根目錄股票資料夾 → 每檔抽關鍵字與每股基準
Step 2  讀舊輸出檔 → 拆事件卡 → 刪過期
Step 3  逐檔搜新聞＋輿情（持股優先，宏觀只補有連動的）
Step 4  查核、打分、排序
Step 5  整份重寫輸出檔
Step 6  跑驗收腳本；不過 → 回 Step 5 整份重寫
Step 7  commit / push ＋ 摘要
```

時間不夠的保底：Step 0 → 1 → 2 → 5 → 6 → 7（刪過期、重算分數、重寫、蓋新時間戳），第八區寫明沒做的 Step。

### Step 0：時間、同步、匯率

1. 執行指令取 `TODAY`、`CUTOFF`。
2. `git pull`（分支是 `master`，不是 `main`；雲端 Claude 拉當前工作分支＋`origin master`）。衝突 → `git stash` → pull → `stash pop`；網路失敗重試 3 次（2s／4s／8s）。
3. 讀舊輸出檔第一行 → `PREV_TS`；讀表頭「覆蓋期間」起日 → `PREV_START`。若 `PREV_START > CUTOFF`，`CUTOFF ～ PREV_START` 是缺口，Step 3 先補搜 HIGH／MEDIUM。
4. 取最近交易日收盤匯率（yfinance `HKD=X`、`CNYHKD=X`；有需要再加 `JPY=X`、`TWD=X`、`IDR=X`）。取不到 → 沿用本地分析檔最新匯率並註明出處。

### Step 1：列出持股（每輪必做，以資料夾為準）

1. 執行：

   ```bash
   python3 gemini/LatestNews_check.py --list
   ```

   每行輸出：`資料夾｜代號｜市場（HK/JP/TW/US/?）｜本地分析：有/無｜輿情：檔名`。市場是 `?` 就讀該資料夾的檔案自行判斷。
   - 沒有 Python：列出根目錄資料夾，排除 `History`、`Log`、`Prompt`、`gemini`、`StkScreenerResult`、`HkReitScreenerResult`、`JpReitScreenerResult` 與 `.` 開頭者；5 位數 = 港股、英文代碼 = 美股（`-KY` 結尾 = 台股）、4 位數看本地檔判斷日股／台股。
2. 每檔只讀需要的段落，記進事件卡：
   - **搜尋關鍵字**：本地分析檔「一句話結論」「本輪最重要的 3 件新事」「後續追蹤／資料缺口」；`Routines_StockAnalysis.md` 輪替表該公司的 `EXTRA_ANALYSIS`（使用者問過的問題，最優先）。
   - **每股基準**：股數口徑（股數＋單位＋日期）、本年預估 EPS／DPU、最新收盤、主要幣別。
   - 本地分析檔「無」→ 改讀資料夾內最新季報／年報 .md 取股數；再不行用 yfinance `sharesOutstanding`，標明來源。
3. 整理「宏觀連動」：只列和本輪持股有關的主題，例：中國房市 → 02318、01426、87001；日銀／JGB → 2971、3455；油價 → 00883、CF、01866；匯率 → 所有外幣財報的持股。持股不在清單上的主題就不搜。

### Step 2：讀舊檔、拆卡（只讀不改）

1. 從頭讀完舊輸出檔（不存在 = 首輪，跳 Step 3），把每則新聞、輿情、傳聞拆成事件卡。**舊排名、分數、每股數字、🆕 都不沿用**。
2. 逐張判定：
   - 日期 < CUTOFF → `刪除（過期）`，沒有例外；仍在發酵就要找到 ≥ CUTOFF 的新進展。
   - 沒日期 → 查出日期；查不到 → `刪除（無日期）`。
   - 對應的持股資料夾已不存在 → `刪除（已出清）`。
   - 其餘 → `保留`，Step 4 重查、重算。
3. 舊下一輪項目：已被本地分析檔涵蓋 → `刪除（已完成）`；建立日 < CUTOFF 且無新證據 → `刪除（過期）`。
4. 舊日曆：已過的刪掉（有結果就併入對應卡 ①）。

### Step 3：逐檔搜尋

**順序**（時間不夠時前面先做完）：
1. 缺口補搜（Step 0.3 有缺口才做）
2. 本地分析結論偏 🔴 的持股
3. 其餘每一檔持股，**每檔至少 1 次搜尋**；台股中小型用「中文名＋代號」
4. 宏觀連動主題（Step 1.3），每個 1–2 次
5. 輿情：先讀本地輿情檔（只取 ≥ CUTOFF 的段落），再搜社群
6. 保留卡 ⑧ 的觀察點已到期 → 查結果併回原卡

**查詢寫法**（一定加年份或月份；窗口跨兩個月就兩個月都搜）：
- 中文：`<公司名> <代號> 公告 <YYYY年M月>`、`<公司名> 法說會`、`<公司名> 回購 <M月>`
- 英文：`<Company> <ticker> news <Month YYYY>`、`<Company> downgrade OR upgrade <Month YYYY>`
- 日文：`<社名> 適時開示 <YYYY年M月>`、`<社名> 株価 急落 OR 急騰`

**來源優先序**：HKEXnews、MOPS 公開資訊觀測站、TDnet／EDINET、SEC EDGAR、公司 IR → Reuters、Bloomberg、Nikkei、財新、經濟日報、工商時報 → 其他媒體 → 論壇。

**輿情平台**：英文 X、Reddit、Seeking Alpha、Yahoo Finance、TipRanks｜台灣 PTT、Dcard、Mobile01、CMoney 股市爆料同學會、HiStock｜華語 雪球、東方財富股吧、moomoo｜香港 LIHKG、香港討論區｜日本 minkabu、kabutan、Yahoo!ファイナンス掲示板、5ch。輿情和新聞一起排名，金額論點一樣要查核與每股化。

抓到金額時，同時記下**原始幣別與單位**（萬／億／百万），之後才能正確每股化。

### Step 4：查核、打分、排序

**每條檢查**：日期 ≥ CUTOFF？讀過原文（不只摘要）？HIGH 有官方 1 或媒體 2？與本地分析一致（不一致標 🔄）？是新進展還是重炒舊聞（重炒不改日期、不標 🆕）？幣別、單位、股數抄對？

**分級**（看對受影響最大那檔的每股影響）：
- HIGH：每股 EPS／配息／淨值變動 ≥ 5%，或治理／法遵重大事件，或央行利率決策
- MEDIUM：1%–5%，或有趨勢指標意義
- LOW：< 1% 或純情緒

**分數**（0–10，寫在標題行；每輪以 TODAY 重算）：
- 幅（0–4）：每股影響 ≥ 10% → 4｜5–10% → 3｜1–5% → 2｜< 1% → 1｜寫不出路徑 → 0
- 廣（0–2）：≥ 5 檔 → 2｜2–4 檔 → 1｜1 檔 → 0
- 急（0–2）：7 天內有決定時點（財報、除息、TOB 截止、央行會議、掛牌）或仍在發酵 → 2｜8–14 天 → 1｜已落幕 → 0
- 險（0–1）：利空 → 1
- 注（0–1）：命中 `EXTRA_ANALYSIS`、本地「3 件新事」或 🔄 → 1

**排序**：HIGH → MEDIUM → LOW；同級分數高 → 低；同分：⭐ 先於 ◐、日期新 → 舊。HIGH ≤ 3 分或 LOW ≥ 7 分 = 分級或分數有錯（降溫卡除外）。

**降溫**：依第 1 節定義處理；降溫卡之後有新進展 → 改新日期、取消降溫、標 🆕。

**篇幅**：MEDIUM＋LOW ≤ 60 則；超過先合併同事件，再刪最低分 LOW（同分刪較舊），記第七區。HIGH 全留。

**可信度**：`⭐` 數字在財報或官方公告找得到｜`◐` 方向對但數字無法完全回查｜`⚠️` 傳聞 → 只放第六區。

**下一輪項目**（第五區，至少 5 條）觸發條件：HIGH 新聞改變某檔每股判斷、🔄 數字衝突（含股數或匯率變動 > 1%）、`EXTRA_ANALYSIS` 有新答案、未來 14 天有關鍵事件。P0 = 7 天內做｜P1 = 下次輪到該公司時｜P2 = 有空再做。

### Step 5：整份重寫輸出檔

1. 收齊事件卡（保留＋新增＋修正）；`刪除` 卡只寫進第七區。
2. 每張卡、每檔持股用 Step 1 的股數與 Step 0 的匯率**重算**每股影響（不沿用舊數字）。
3. 同事件合併成一張卡，依 Step 4 排序編 N1、N2…；1.2 = N1～N5；1.3 = 所有 🆕。
4. 依第 5 節寫法重新組句（舊卡也要重寫，不可貼舊句；已過的日期不可留在 ⑧）。
5. 寫檔前跑一次第 6 節「寫檔前自檢」。
6. **執行指令取台北時間**放第一行（必須晚於 `PREV_TS`），然後整檔寫入一次。

### Step 6：驗收

```bash
python3 gemini/LatestNews_check.py --today TODAY --prev "PREV_TS"   # 首輪省略 --prev
git diff --stat gemini/LatestNewsResult.md                          # 必須有變動
```

最後一行必須是「問題 0 個」。不過 → 回 Step 5 **整份重寫**，不是局部修。沒有 Python 時，照第 6 節自檢逐項人工檢查。

人工抽查（腳本抓不到）：
- 只讀第一、二區，會漏掉任何 HIGH、🆕 或 P0 嗎？
- 挑 3 則 HIGH：不查 Google 看得懂「發生什麼 → 影響哪檔 → 每股多少 → 接下來看什麼」？
- 挑 5 個金額（至少 2 個港股）驗算「金額 ÷ 股數 × 匯率」＝文中每股數字？
- 每則 ⑧ 的日期都在 TODAY 之後？⑥ 是最新收盤？

### Step 7：交付

1. `git add gemini/LatestNewsResult.md`
2. commit：`LatestNews: YYYY-MM-DD 30-day scan (CUTOFF ~ TODAY)`
3. push：Gemini 本機 `git push origin master`；Claude 雲端推到指定工作分支。失敗重試 3 次（2s／4s／8s）。
4. 對話中輸出摘要：

```
✅ LatestNews — YYYY-MM-DD HH:MM
- 持股：N 檔（港 a／日 b／台 c／美 d；本輪新增資料夾：…／移除：…）
- 覆蓋：CUTOFF ～ TODAY｜排行榜 T 則（🆕 X）｜傳聞 R 則｜刪除 K 條｜修正 J 條
- 驗收：問題 0 個｜匯率：1 USD = X HKD｜1 RMB = X HKD（日期）
- 最重要 N1～N3（含每股影響）：① … ② … ③ …
- 下一輪 P0：…

```

## 5. 輸出檔寫法

### 5.1 白話規則

- **說人話測試**：剛入行的同事讀完，不查 Google 能答出「發生什麼？我手上 1 股多/少多少錢？接下來盯什麼？」
- **術語第一次出現就補白話**，例：「DPU（REIT 每單位配息）」「LTV（負債 ÷ 資產）」「TOB（公開收購）」「1 碼（0.25 個百分點）」「除淨（香港用語＝除息）」「HIBOR（港元借款基準利率）」。
- **標題就是結論**：❌ `日銀新階段` → ✅ `日銀暗示加快升息 → 借浮動利率的 2971 配息壓力變大`。
- **數字要有比較基準**：❌ `PMI 50.1` → ✅ `PMI 50.1（上月 49.8；50 以上代表擴張）`。
- **寫影響路徑**：新聞 → 經營變數 → 財報科目 → 每股 EPS／配息／淨值。寫不出 = 跟持股無關 → 刪。
- **代號標交易所**：`02318（港交所）`、`2971（東證）`、`2881（台灣證交所）`、`UHS（NYSE）`。
- 一句一件事；不用「暴雷」「大補血」代替數字；不寫「市場普遍認為」卻不說是誰。

### 5.2 每股化

- **要每股化**：營收、獲利、減損、資本支出、募資、回購、股利總額、併購、借款、罰款、財測、補貼等「跟某檔持股有關的金額」。REIT 換算每單位／每口。
- **不用每股化**：比率、百分比、市場層級金額（指數成交額、政策總規模）；但若影響持股，⑤ 仍要寫該檔每股影響。
- **分母**：本地分析檔「股數口徑聲明」→ 交易所月報／最新財報 → yfinance（標來源）。台股不可拿股本金額當股數（股本 ÷ 面額 10 元＝股數）。股數變動 > 1% 改用新股數並標 🔄。
- **三種寫法**：
  - 基本式：`減損 1,655 萬 HKD（每股 −0.0083 HKD）`
  - 完整式（每檔第一次出現）：`減損 1,655 萬 HKD（÷ 20.00 億股 = 每股 −0.0083 HKD；股數：9 月月報表）`
  - 影響式（⑤、1.2 必用）：`🔴 每股 −0.0083 HKD，約當 FY2026E EPS 的 −2.1%（實績；一次性）`——必含每股金額＋佔 EPS／DPU 百分比＋一次性或常態性；推估寫 `推估：假設…`。
- **幣別範例**：
  - 港股人民幣財報：`每股 +0.030 HKD（原始 +0.026 RMB，1 RMB = 1.1682 HKD）`
  - 港股美元財報（01426）：`每單位 0.031 HKD（原始 0.004 USD，1 USD = 7.78 HKD）`
  - ADR（TLK）：`每 1 ADS −0.34 USD（原始 −61.6 IDR／股 × 100 股；1 USD = 18,125 IDR）`
  - ❌ `每股約 +0.024 RMB`（港股只寫人民幣）、❌ `每股派息 2.51 RMB＝2.90 HKD`（人民幣在前）

### 5.3 單則欄位（新聞與輿情共用）

HIGH 寫滿 ①～⑩；MEDIUM 至少 ①②④⑤⑧⑩；LOW 至少 ①⑤⑩。輿情的 ① 寫「誰在哪個平台說了什麼」，⑦ 寫多空雙方說法，⑨ 寫查核結果。

  - **① 發生什麼**：2–3 句；多次進展用子條目時間軸
    - MM-DD：…
  - **② 關鍵數字**：數字＋單位＋日期＋比較基準＋代表什麼；金額接每股金額
  - **③ 背景**：1–2 句前情（CUTOFF 前的舊事實要標日期）
