# ArrangePublicOpinionMd — 執行指南

把每個公司資料夾內零散的「輿情／新聞／討論區」`.md`，依年份合併成 `{YYYY}_PublicOpinion.md`，驗證後刪除原檔，最後產出報告。

## 三條底線（不可妥協）

1. **只動輿情檔**：年報、季報、公司公告 report **不納入、不刪除、不改名**（§3 黑名單）。
2. **先驗證再刪除**：原檔內容確認出現在彙整檔前，**絕不刪除**（§5）。
3. **原文照抄**：只做標題階層下降 + 來源註記，**不摘要、不改寫、不刪節**（§4）。

> 灰色地帶一律偏向「不動」：寧可漏整理，也不可誤刪財報。

## 0. 執行方式（固定，無參數，不要反問使用者）

| 項目 | 固定行為 |
| :--- | :--- |
| 處理範圍 | **全部**公司資料夾、**全部**年份（一年一份彙整檔） |
| `discard/` | 完全跳過 |
| 動作 | **實際寫檔與刪檔**（無 dry-run） |

`ROOT` = FinancialReport repo 根目錄（本機 clone，Windows 通常是 `d:\FinancialReport`）。

**首選做法**：直接執行本 Skill 附帶的參考實作，它已完整實作 §1–§6：

```bash
python .claude/skills/ArrangePublicOpinionMd/scripts/arrange_public_opinion.py --root <ROOT>
```

> Windows 中文路徑用 `python -c "…"` inline 會亂碼；一律用 `.py` 檔執行，全程 `encoding='utf-8'`。
> 若不使用該腳本而手動執行，仍須完全遵守以下 §1–§6 規則。

## 1. 流程

| Phase | 任務 |
| :--- | :--- |
| 0 | 前置檢查（目錄、git 狀態） |
| 1 | 掃描公司資料夾第一層所有 `.md` |
| 2 | 分類：輿情檔 / 排除檔 → 判定年份 |
| 3 | 依年份合併寫入 `{YYYY}_PublicOpinion.md` |
| 4 | 完整性驗證（逐檔比對） |
| 5 | 驗證通過才刪除原檔 |
| 6 | 產生 `Log/ArrangePublicOpinionMd_Summary_{yyyyMMdd}.md` |

## 2. Phase 0 — 前置檢查

| 檢查項 | 未通過時 |
| :--- | :--- |
| `ROOT` 底下有 `AGENTS.md` 與多個公司資料夾 | **立刻中止**並回報路徑錯誤 |
| `git status` 可執行 | 繼續，但報告註明「無 git 保護，刪除不可復原」 |
| 工作區乾淨（無未提交 `.md` 變更） | 提醒使用者本 Skill 會刪檔、建議先 commit/stash；使用者堅持則繼續 |

**公司資料夾** = `ROOT` 第一層目錄，排除：`.git` `.github` `.claude` `.agents` `Log` `Prompt` `AnalysisResult` `StkScreenerResult` `discard`。每個資料夾**只掃第一層**，不遞迴。

## 3. Phase 2 — 分類

判定順序：**黑名單 → 白名單 → 內容判定**。黑名單優先權最高。
> 完整關鍵字與 regex 清單以 `scripts/arrange_public_opinion.py` 的 `BLACK_KEYWORDS` / `BLACK_REGEX` / `WHITE_REGEX` / `SOURCE_NAMES` 為準（要擴充改那裡，避免兩處失聯）。

### 3.1 黑名單（命中即完全不動）

| 類別 | 代表關鍵字／樣式 |
| :--- | :--- |
| 年報／半年報／季報 | `annual`、`年報`、`有価証券報告書`、`interim`、`中期報告`、`quarter`、`四半期`、`Q1`–`Q4`、`_H1`/`_H2` |
| 美股／日股申報 | `10-K`、`10-Q`、`20-F`、`6-K`、`8-K`、`DEF 14A`、`決算短信`、`決算説明`、`適時開示` |
| 公告／財報本體 | `公告`、`announcement`、`股東會`、`notice`、`Official_IR`、`業績公告`、`未經審核`、`營運統計`、`財務報告`、`財報`※、`earnings_release` |
| 制式機器檔名 | EDINET `^S\d{3}[A-Z0-9]{4}\.md$`、SEC XBRL `^[a-z]{2,6}-\d{8}\.md$`、`^ltn\d+\.md$`、純數字編號 `^\d{8,}\.md$`、8 碼日期開頭公告 `^\d{8}(?![_\-\d])`、選股排名 `^\d{2}-[0-9A-Za-z]{2,6}-.*\.md$` |
| 台股財報代碼 | `F04`、`FE4`、`FI4`、`_AI[0-9A-Z]`（如 `2025_2881_20260612F04.md`、`202601_2881_AI1.md`） |
| 分析產出／系統檔 | `*Analysis*.md`、`*_Summary_*.md`、`conversion_summary.md`、`README.md`、`index.md`、`prompt.md`、`AGENTS.md`、`CLAUDE.md`、`Routines_*.md`、`*_reconciliation_*.md` |
| 個人投資筆記／估值速記 | `Orange.md`（不分大小寫）——非輿情彙整、非公司年報季報，僅為個人估值筆記，一律不納入、不刪除 |
| 輸出檔本身 | `{YYYY}_PublicOpinion.md`（含 `_part{n}`）、舊版 `{YYYY}_輿情彙整.md` → 不併入自己、不刪除，依 §4.1 遷移 |

※ `財報狗`／`StatementDog` 是輿情來源，**不算財報**（regex 用 `財報(?!狗)`）。

> [!CAUTION]
> 白名單 W1（`yyyyMM_`）會誤中台股財報檔（`202601_2881_AI1.md`）——這就是黑名單必須先跑的理由。

### 3.2 白名單（未中黑名單且符合任一）

| # | 條件 | 範例 |
| :--- | :--- | :--- |
| W1 | `^\d{4}(0[1-9]\|1[0-2])_.+\.md$` | `202607_Xueqiu.md` |
| W2 | `^\d{4}_[^\d].*\.md$` | `2026_reddit.md` |
| W3 | 含 `輿情`/`新聞`/`討論`/`sentiment`/`news`/`feed` | `輿情_20260725.md` |
| W4 | `^\d{4}-\d{2}-\d{2}.*\.md$`（含日期異常者） | `2026-07-04.md`、`2026-56-10.md` |
| W5 | `^_SubAgentC_feed_\d{8}_Round\d+\.md$` | `_SubAgentC_feed_20260622_Round1.md` |
| W6 | 含已知輿情來源名 | `PTT`、`Dcard`、`Mobile01`、`股市爆料同學會`、`財報狗`、`Reddit`、`SeekingAlpha`、`TipRanks`、`Xueqiu`/`雪球`、`東方財富`、`Futu`、`LIHKG`、`Kabutan`、`5ch`、`Reuters`、`鉅亨`、`udn`… |

### 3.3 灰色地帶 → 內容判定（強制）

黑白名單都沒中者，**必須**讀前 60 行 + 中段 20 行再判：

| 判定 | 特徵字串（出現任一） |
| :--- | :--- |
| **排除** | `合併財務報告`、`會計師核閱/查核`、`資產負債表`、`綜合損益表`、`現金流量表`、`Form 10-K/10-Q`、`ITEM 1. BUSINESS`、`有価証券報告書`、`四半期報告書`、`股東常會`、`董事會決議` |
| **納入** | `輿情`、`討論`、`留言`、`網友`、`看多/看空`、`情緒`、`鄉民`、`貼文`、`Reddit`、`PTT`、`雪球`、`Seeking Alpha`、`來源網站`、`抓取方式`、`新聞` |
| **都無／都有** | **不納入、不刪除**，列入報告「人工確認清單」 |

### 3.4 年份判定

依序取第一個成功者；年份須落在 `2000`–`當年+1`，否則往下一項：

| 序 | 來源 | Regex | 例 |
| :--- | :--- | :--- | :--- |
| 1 | `yyyyMM_` 前綴 | `^(\d{4})(?:0[1-9]\|1[0-2])_` | `202607_Xueqiu.md` → 2026 |
| 2 | `YYYY-MM-DD` 前綴 | `^(\d{4})-\d{2}-\d{2}` | `2026-56-10.md` → 2026 |
| 3 | 檔名內 8 碼日期 | `(20\d{2})\d{4}` | `輿情_20260725.md` → 2026 |
| 4 | `YYYY_` 前綴 | `^(\d{4})_` | `2026_reddit.md` → 2026 |
| 5 | 內文前 40 行首個日期 | `(20\d{2})[-/年]\d{1,2}` | → 該年 |
| 6 | 檔案 mtime | — | → 該年（**報告須標記「年份為推定」**） |

**不合併跨年**：2025 的輿情絕不寫進 `2026_PublicOpinion.md`。

## 4. Phase 3 — 合併

### 4.1 輸出檔

`{ROOT}/{公司資料夾}/{YYYY}_PublicOpinion.md`，每公司每年一份；超過 20 MB 才切 `_part{n}`。該年只有 1 個輿情檔**照樣合併**（等於正規化檔名）。

**舊版檔名遷移（每次執行先做）**：資料夾內若有 `{YYYY}_輿情彙整.md`——
- 新檔不存在 → `git mv` 改名為 `{YYYY}_PublicOpinion.md`，內容原封不動，之後以它為 merge 目標。
- 兩者都在 → 舊檔當一般來源併入新檔（保留其 `source-file` 註記），通過 §5 才刪。
- 結果寫進 Phase 6 報告。

### 4.2 排序

同年份來源檔依「檔名解析出的 `yyyyMM`（無月份者記 `12` 排最後）→ 完整檔名字典序」升冪。

### 4.3 檔案結構（強制模版）

````markdown
# [{公司資料夾名稱}] {YYYY} 年 輿情彙整

> 本檔由 **ArrangePublicOpinionMd Skill** 自動彙整，內容為本資料夾 {YYYY} 年度所有「輿情／新聞／討論區」`.md` 的原文合併。
> 不含年報、季報、公司公告 report。
> 最後彙整時間：{YYYY-MM-DD HH:mm}｜本次併入：{N} 檔｜累計併入：{M} 檔

## 目錄
- [{YYYY}-{MM} · {來源標題}](#錨點)

<!-- body:start -->

## {YYYY}-{MM} · {來源標題}

<!-- source-file: 202607_Xueqiu.md | bytes: 12345 | sha1: 8f14e45f… | merged-at: 2026-08-25 -->

{原檔內容，原文照抄}

---
````

| 項目 | 規則 |
| :--- | :--- |
| 章節標題 | `## {YYYY}-{MM} · {來源標題}`；標題 = 檔名去掉日期前綴與 `.md`（`202607_Xueqiu.md` → `Xueqiu`），無法解析就用完整檔名 |
| 來源註記 | 每章節第一行**必須**是 `<!-- source-file: … -->`（原檔名、bytes、sha1、併入日期）——重跑去重與驗證的依據，**不可省略** |
| 標題階層 | 原檔 ATX 標題一律**下降 2 級**（`#`→`###`），最深 `######`；反引號區塊（``` / ~~~）內的 `#` 不動；**內容文字一字不改** |
| 分隔線 / 編碼 | 章節結尾補 `---`；`utf-8`、換行 `\n`、檔尾保留一個換行 |

### 4.4 重跑（冪等）

1. 讀出彙整檔內所有 `<!-- source-file: {name} … -->` 的 `{name}` 集合。
2. 已在集合內 → **不重複併入**（仍可進 Phase 5 刪除，前提是通過 §5）。
3. 新檔 → **append 到 `<!-- body:start -->` 之後的檔尾**，再更新頂部目錄與統計。
4. **禁止整檔重寫覆蓋既有內容**；只允許 append + 更新頭部。無 `body:start` 標記的舊檔，整份內容原封保留為 body 前段。

### 4.5 寫入安全

先寫 `{YYYY}_PublicOpinion.md.tmp` → 確認 size > 0 且可讀 → 原子性取代正式檔 → 刪暫存。
寫入失敗 → 保留原檔、記錄錯誤、**跳過該公司該年度的刪除**，繼續下一家。

## 5. Phase 4/5 — 驗證與刪除（安全閘門）

### 5.1 刪除前必須全過

| # | 檢查 | 不過 |
| :--- | :--- | :--- |
| C1 | 彙整檔存在且 size > 0 | 不刪任何檔 |
| C2 | 彙整檔內有該原檔的 `<!-- source-file: {原檔名} … -->` | 不刪該檔 |
| C3 | 原檔去除空白與 `#` 後的前 200 字元，能在同樣正規化的彙整檔中找到 | 不刪該檔 |
| C4 | 彙整檔 size ≥ 本次已併入原檔 size 總和 × 0.95 | 不刪任何檔 |
| C5 | 該檔未命中 §3.1 黑名單（雙重保險） | 不刪該檔 |

### 5.2 刪除規則

- ❌ **禁止萬用字元**：指令不可出現 `*`、`?`、`rm -rf`、`Remove-Item -Recurse`；一次一個**明確單一路徑**。
- ✅ **優先用 git**：`git rm "<path>"`，保留可復原性。
- ❌ **只刪 `.md`**，永不刪資料夾；年報／季報／公告／分析報告／彙整檔本身一律不刪。
- ✅ **逐檔記錄**（公司、檔名、bytes、併入的彙整檔）供 Phase 6。

```bash
git rm "2881富邦金/202607_PTT.md"      # 逐檔、寫全路徑
```

**復原指引（寫進報告）**：`git checkout HEAD -- "<公司資料夾>/<被刪檔名>"`

## 6. Phase 6 — 總結報告

輸出 `{ROOT}/Log/ArrangePublicOpinionMd_Summary_{yyyyMMdd}.md`（`Log` 不存在就建立），並在最終回覆中以中文摘要呈現。

| Section | 內容 |
| :--- | :--- |
| 1 統計概覽 | 掃描公司數／`.md` 總數／輿情檔數／排除（年報季報公告）／排除（分析系統檔）／產生更新彙整檔數／已刪除原檔數／待人工確認數 |
| 2 各公司明細 | 公司｜年份｜彙整檔｜本次併入｜已刪除｜備註（含舊檔遷移、年份推定） |
| 3 排除清單 | 公司｜檔名｜排除原因｜命中規則（要看得出「為什麼沒動它」） |
| 4 人工確認清單 | 公司｜檔名｜判定困難原因｜建議 |
| 5 錯誤與跳過 | 公司｜檔名｜錯誤／跳過原因（含空檔清單） |

## 7. 異常處理

| 情況 | 動作 |
| :--- | :--- |
| 單檔讀取失敗（編碼、權限） | 記錄 → 跳過該檔（不刪）→ 續下一檔 |
| 彙整檔寫入失敗 | 記錄 → 該公司該年度**完全不刪檔** → 續下一家 |
| 年份無法判定 | mtime 推定並標記；mtime 也異常 → 列人工確認，不動該檔 |
| 空檔（0 bytes） | 不併入、列報告、**不自動刪除** |
| 彙整檔 > 20 MB | 切 `_part{n}`，並在 part1 頂部列出所有 part |
| 中途中斷 | 已寫入的彙整檔保留；未驗證的原檔一律不刪 |

## 8. 完成後

1. 回覆中呈現 §6 統計概覽與各公司明細（中文）。
2. 明確回報：產生幾份彙整檔、刪了幾個原檔、哪些被排除（年報／季報／公告）、哪些需人工確認。
3. 在 git repo 內則提交變更（如 `chore: 合併各公司輿情 md 為年度彙整檔`）；**推送分支依使用者指示**，不要自行推 `master`。
